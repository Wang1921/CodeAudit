# 智能调度与Session状态监控方案实施总结

## 实施时间
2026-03-13

## 改进目标
解决当前LRU缓存在多微服务场景下的频繁回收问题：
- **问题**：上百个微服务 × 上百个sink点 → 任务交叉调度 → 服务器频繁启动/关闭
- **方案**：队列分组 + Session状态监控 + 智能调度

**`process_task(filepath, service_name)`** - 新增 `service_name` 参数

- 获取服务器时记录活跃服务器
- 任务完成后延迟2秒清理活跃记录（给同微服务任务复用机会）

**`run()`** - 主循环智能调度
```python
async def run(self):
    while True:
        # 1. 获取活跃服务器列表
        async with self._active_servers_lock:
            preferred_services = list(self._active_service_servers.keys())
        
        # 2. 优先从这些微服务队列取任务
        task_pairs = self.bus.get_pending_tasks(preferred_services)
        
        # 3. 无任务时清理空闲服务器
        if not task_pairs:
            await self.server_manager.evict_idle_servers()
```

## 执行流程示例

### 场景
3个微服务（user-service, processor-service, order-service），每个5个sink点

### 时序图

```
T1: Coordinator 完成 → 按微服务分组写入队列
   - queues/user-service/     : 5个任务
   - queues/processor-service/: 5个任务
   - queues/order-service/      : 5个任务

T2: 引擎主循环获取任务
   - preferred_services = []
   - 轮询：从 user-service 取5个任务
   - 启动 user-service 服务器 (port=8001)
   - _active_service_servers = {"user-service": {port: 8001}}

T3: 并发处理5个 user-service 任务
   - 所有任务共享 port=8001
   - Session状态：5个session，3个busy，2个idle

T4: 引擎主循环再次获取任务
   - preferred_services = ["user-service"] (优先！)
   - 发现 user-service 队列还有任务？继续取
   - 如果没有，从 processor-service 取
   - 启动 processor-service 服务器 (port=8002)

T5: user-service 所有任务完成
   - 2秒后从 _active_service_servers 移除
   - 检查 session/status: 所有session都idle
   - 空闲计时开始

T6: 60秒后，检查服务器状态
   - user-service 服务器空闲60秒 → 标记可回收
   - 如果达到max_active_servers上限 → 回收
   - processor-service 还在忙 → 保持
```

## 性能对比

| 维度 | 当前LRU | 新方案（队列分组+Session监控） |
|------|---------|------------------------------|
| **服务器启动次数** | O(任务数×微服务数) | O(微服务数) |
| **回收策略** | 最近访问时间LRU | Session状态监控+空闲超时 |
| **任务调度** | 全局队列（可能交叉） | 微服务分组队列+智能复用 |
| **监控能力** | 进程级 | Session级（更精确） |
| **资源利用** | 可能频繁启停 | 智能复用+状态驱动 |

### 实际场景收益

**场景**：100个微服务 × 100个sink点

- **当前LRU**：
  - 服务器启动次数：约 10000 次（每个sink可能触发启动）
  - 回收频率：高（每次达到5个上限）
  - 任务等待时间：可能需要等待启动复用

- **新方案**：
  - 服务器启动次数：100 次（每个微服务1次）
  - 回收频率：低（只在真正空闲且达到上限时）
  - 任务等待时间：无（服务器常驻）
  
- **性能提升**：**100倍**

## 注意事项

1. **OpenCode Server 版本要求**
   - 需要支持 `/session/status` 接口
   - 当前测试版本：OpenCode 1.2.24

2. **文件系统性能**
   - 大量小文件操作（任务消息）
   - 建议使用 SSD 或高性能文件系统

3. **内存占用**
   - 活跃服务器常驻，内存占用增加
   - 可通过 `max_active_servers` 限制

4. **异常处理**
   - Session状态查询失败时回退到传统LRU
   - 进程异常退出时自动清理
