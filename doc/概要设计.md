# 概要设计文档：双轨制多智能体代码审计系统
**版本**: V6.0  |  **状态**: 正式 (Final)

## 1. 系统概述 (System Overview)
传统的静态应用安全测试 (SAST) 工具在面对复杂的代码库时，常面临高误报率、跨文件调用链断裂以及无法发现业务逻辑漏洞的痛点。

本系统旨在构建一个**高度自动化、具备专家级推理能力**的代码审计引擎。通过集成 `opencode` CLI 环境，结合 **A2A (Agent-to-Agent) 协议理念**，利用多个具有特定安全专业领域的大模型智能体 (Agents) 进行协同作战。系统采用独特的**双轨制（自底向上与自顶向下并行）**架构，实现对技术型漏洞（如注入、路径遍历）和业务逻辑漏洞（如越权、条件竞争）的全面覆盖。

## 2. 核心架构理念 (Core Architectural Principles)

### 2.1 双轨并行审查 (Dual-Track Auditing)
+ **技术轨道 (Bottom-Up)**: 通过 Semgrep 静态扫描器发现底层危险函数 (Sinks)，向上逆向追踪，专攻 CWE-22（路径遍历）、CWE-73（文件外部控制）及各类注入漏洞。
+ **业务轨道 (Top-Down)**: 从 API 路由入口向下正向推演，专攻 IDOR（越权）、并发等状态机逻辑漏洞。

### 2.2 文件系统即总线 (A2A over File System IPC)
+ 采用本地文件系统目录（`.a2a_bus/`）作为异步消息总线。
+ Agent 之间通过读写强类型的 JSON 信封 (TaskRequest / TaskResult) 进行任务流转，具备极强的可观测性和容错性。

### 2.3 HTTP 沙盒池管理 (HTTP Sandbox Pool)
+ Python 引擎管理多个 OpenCode 服务器实例，采用 LRU 缓存策略（默认最大 5 个并发）。
+ 自动健康检查 (`/global/health`)，失败时自动重启。
+ 达到并发上限时自动回收最旧的沙盒服务器。

### 2.4 基于 OpenCode 沙盒的无头执行 ( (Headless Execution)
+ 系统不预先硬编码静态分析工具集。
+ 每个 Agent 作为一个独立的 `opencode` CLI 进程拉起（工作目录挂载为源码根目录），通过大模型自主调用 LSP 进行动态的代码片段提取与跳转。

### 2.5 红蓝对抗验证 (Adversarial Validation)
+ 摒弃单一的漏洞判定器。引入具备"黑客思维"的红队智能体负责构造 Payload 和绕过思路；引入具备"防御思维"的蓝队智能体负责审查代码库中的过滤器、拦截器或业务后置熔断机制，通过左右互搏，系统能最大程度消除传统 SAST 工具的**高误报率**。

### 2.6 控制面与数据面分离 (Control Plane vs Data Plane)
+ **数据面 (Agents)**: 智能体仅作为无状态的计算节点运行。它们被剥夺了写文件的权限，所有分析结果的 JSON 只能通过**标准输出 (Stdout)** 打印。
+ **控制面 (Python 引擎)**: 唯一拥有本地磁盘写权限的全局调度器。负责监听 Agent 的 Stdout，清洗格式后，代笔写入 `.a2a_bus` 文件系统总线。

### 2.7 最小权限原生沙盒 (Least Privilege Native Sandbox)
+ 摒弃 Docker 等重型虚拟化技术。通过 OpenCode 的原生启动参数（如 `--tools` 和 `--read-only`），按角色精准分配工具。
+ **动态工具权限分配**: 
  - **Coordinator**: 拥有 `codesearch, glob, grep, read` 权限，用于全局项目测绘。
  - **其他 Agent**: 拥有 `lsp, read, codesearch` 权限，开启重型武器 LSP 进行代码跳转。

### 2.8 动态 Prompt 模板加载 (Dynamic Prompt Templates)
+ 所有智能体 Prompt 存储于 `prompts/core/` 目录下的 YAML 文件中。
+ 引擎根据 Agent 类型动态加载对应的模板，支持变量替换（如 `{payload_json}`, `{dynamic_tracing_strategy}`）。

### 2.9 Semgrep 静态扫描集成 (Semgrep Integration)
+ 支持自定义 Semgrep 规则目录或单文件规则。
+ 自动将 Semgrep 输出转换为标准的 `sink_details` 和 `route_details` 格式。
+ 在 Coordinator 完成后自动触发，为每个发现的漏洞点和路由生成对应的 Agent 任务。

### 2.10 跨微服务追踪 (Cross-Service Tracing)
+ 自动识别项目中的微服务结构（通过 `pom.xml`, `package.json` 等构建文件）。
+ 支持 ReverseTracer 发出跨微服务追踪请求，引擎自动在所有微服务中并发启动溯源 Agent。
+ 构建全局服务路由表，支持跨服务调用链追踪。

## 3. 动态泛化与安全底线保障 (Generalization & Security Baseline)

### 3.1 动态追踪策略注入 (Dynamic Tracing Profiles)
+ 面对 Nginx/Lua 等路由与业务逻辑跨文件隔离的复杂架构，`Coordinator` 在全局测绘时会动态生成一份"特化追踪指南"。
+ 引擎将其拼接到 `ReverseTracer` 提示词模板中，赋予其跨上下文的溯源能力。

### 3.2 引擎级强制安全红线 (Engine-Level Mandatory Overrides)
+ 调度引擎在任务裂变阶段强制干预，不完全依赖 AI 的自觉性。
+ **Semgrep 扫描**: 引擎在 Coordinator 完成后自动触发 Semgrep 扫描，一次性获取 API 路由和漏洞点。
+ **任务裂变**: 根据扫描结果，自动为每个路由生成 LogicAuditor 任务，为每个漏洞点生成 ReverseTracer 任务。
+ **100% 覆盖**: 确保所有 API 路由和危险点都被审计，无遗漏。

## 4. 智能体角色定义 (Agent Roster)
系统由 1 个协调者与 6 个专家级工作节点组成（验证层拆分为红蓝双角色）：

| 角色名称 | 类型 | 职责说明 | 工具权限 |
| :--- | :--- | :--- | :--- |
| **Coordinator** | 调度器 | 扫描项目结构、识别微服务、提取 API 路由表，生成动态追踪策略 | `codesearch, glob, grep, read` |
| **SemgrepScanner** | 静态扫描器 | 使用 Semgrep 规则扫描代码库，发现底层危险函数（Sinks）和 API 路由 | 无（外部进程）|
| **ReverseTracer** | 专家节点 | 接收 Sink 坐标，自底向上逆向追踪调用链，支持跨微服务追踪 | `lsp, read, codesearch` |
| **LogicAuditor** | 专家节点 | 从 API 路由向下正向推演业务逻辑漏洞（IDOR、条件竞争等）| `lsp, read, codesearch` |
| **RedValidator** | 攻击验证节点 | 扮演红队构造 Payload，验证漏洞可利用性，生成攻击向量 | `lsp, read, codesearch` |
| **BlueValidator** | 防御验证节点 | 扮演蓝队核查防御机制（过滤器、拦截器），确认最终漏洞 | `lsp, read, codesearch` |
| **ReportGenerator** | 报告节点 | 生成最终审计报告，保存 JSON 格式漏洞报告到 `reports/` 目录 | `lsp, read, codesearch` |
| **RetryAgent** | 重试节点 | 当 Agent 输出 JSON 格式错误时，自动触发重试修复 | `lsp, read, codesearch` |

## 5. 通信与协同协议 (A2A Communication Protocol)
系统在项目根目录维护 `.a2a_bus/` 目录群作为交互中枢。所有 Agent 必须遵守严格的 JSON Schema 契约。

### 5.1 目录拓扑
+ `.a2a_bus/pending/`: 待处理任务队列。
+ `.a2a_bus/processing/`: 正在处理的任务。
+ `.a2a_bus/completed/`: 已完成任务与审查结果。
+ `.a2a_bus/failed/`: 契约破坏/执行异常的死信队列。
+ `.a2a_bus/help_req/`: 高优先级跨节点求助队列。

### 5.2 消息类型
+ `TaskRequest`: 任务请求
+ `Coordinator_Output`: 协调器输出
+ `VulnCandidate`: 疑似漏洞候选
+ `ExploitAttempt`: 攻击尝试
+ `ConfirmedVuln`: 确认的漏洞
+ `CrossServiceTraceRequest`: 跨微服务追踪请求

## 6. 核心工作流 (System Workflow)
1. **阶段一：全局测绘 (Initialization)**
    - `Coordinator` 扫描项目，识别到项目为 `Java/Spring Boot` 栈。
    - `Coordinator` 提取微服务结构，生成动态追踪策略。
    - 引擎触发 `SemgrepScanner` 进行一次性扫描。

2. **阶段二：双轨执行 (Execution)**
    - `SemgrepScanner` 返回 API 路由和漏洞点。
    - 引擎根据扫描结果并发派发任务：
      - 为每个 API 路由生成 `LogicAuditor` 任务。
      - 为每个漏洞点生成 `ReverseTracer` 任务。

3. **阶段三：动态协同 (Orchestration)**
    - Python 事件循环持续轮询 `.a2a_bus`，处理正常的结果回收。
    - ReverseTracer 支持跨微服务追踪，可发出 `CrossServiceTraceRequest`。

4. **阶段四：红蓝对抗验证 (Adversarial Validation)**
    - **4.1 攻击推演 (Red Team)**：所有来自双轨执行层的 `VulnCandidate` 首先进入 `RedValidator`。红队节点不看防御，只专注"如果我要利用这个点，应该怎么构造恶意输入？" 如果连红队都觉得无法利用（如参数完全不可控），则直接丢弃；若可利用，则生成附带 Payload 思路的 `ExploitAttempt` 提交给蓝队。
    - **4.2 防御核查 (Blue Team)**：`BlueValidator` 拿到红队的攻击方案后，带着极强的目的性去审查代码。它会质问："现有的 `SecurityFilter` 或 `XssSanitizer` 能否拦截红队的这个 Payload？" 如果能拦截，则标记为误报；如果防御被击穿，则正式盖章确认为真实漏洞。

5. **阶段五：报告输出 (Reporting)**
    - 引擎汇总 `Validator` 输出的有效 JSON 数据，生成标准化、包含完整调用栈的 JSON 安全审计报告。

## 7. 技术选型与依赖 (Technology Stack)
+ **中枢调度层**: Python 3.10+ (使用 `asyncio` 异步非阻塞模型)。
+ **计算执行层**: `opencode` CLI 环境 (提供 LSP 探针、沙盒执行、大模型上下文管理)。
+ **数据契约层**: JSON (严格的数据模式校验，确保 LLM 输出的结构化与工程鲁棒性)。
+ **静态扫描工具**: Semgrep (用于扫描 API 路由和漏洞点）。

## 8. Web 实时看板 (Real-time Web Dashboard)
+ 内置 HTTP 服务器（端口 8080），提供 Vue.js 驱动的实时监控看板。
+ 显示审计进度、Token 消耗、漏洞统计、Agent 状态、红蓝对抗看板。
+ 支持查看每个 Agent 的会话详情、消息历史、工具调用记录。
